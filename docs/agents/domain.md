# Domain docs

This repository uses one shared domain context. Paths below are relative to the repository root.

Before exploring a task, read `GLOSSARY.md` and any relevant decisions under `docs/adr/`.

If either is absent, proceed silently. Create domain documentation only when terms or decisions are actually resolved.

Use the glossary's vocabulary in code, documentation and beads. Surface terminology conflicts and contradictions with existing ADRs rather than silently overriding them.
