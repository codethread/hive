# Authorized manual recovery

Use the selected endpoint and preserve supplied actor identity throughout. Read `beeswax beads sync --help`, native `br sync --help` and the [publication preflight](../../repository-setup/references/publication.md#before-exchange) for supported operations and native prerequisites. The preflight is also available through `beeswax skills file repository-setup references/publication.md`. Choose reconciliation from the observed failure, not a fixed flush/import recipe.

1. **Confirm authority and quiescence.** Retain the user's recovery authorization and identify every writer sharing this database: sessions, workers, scheduled commands and publication processes. Coordinate stopping and later resuming them through their owning tools. For Bee/Colony, read `bee stop --help` and `colony skills get operations`; sleeping Colony leaves detached workers running, and request closure or quiet logs do not prove a process stopped. Verify writer termination or acknowledged suspension independently. Agree coordination with other clones/hosts before exchanging shared tracker history. Keep the hold if quiescence cannot be established.

2. **Preserve evidence before native operations.** Save the failure output and alert observation, Git status and relevant commit IDs, live JSONL and native base, any pending merge receipt and its referenced artifacts, and a consistent SQLite backup including audit history outside the affected checkout. Preserve any WAL state using an appropriate SQLite backup procedure. These backups require recovery quiescence; routine publication does not copy the database. Keep unpublished local and incoming versions separately:
   - `.beads/hive-sync-incoming.jsonl` pins the failed attempt's accepted remote snapshot; `.beads/hive-sync-base.jsonl` pins its Git common-ancestor snapshot. Retain these files with their Git revisions before a retry replaces them.
   - Neither input is the live `.beads/issues.jsonl` export or canonical native `.beads/beads.base.jsonl`. Native `br` owns canonical database/export/base writeback; the last local native base is not necessarily the Git common ancestor.

   Ordinary native commands may import or export automatically; even a successful task creation can replace incoming changes. Do not use tracker bookkeeping as the incident record.

3. **Diagnose without reconciliation effects.** Use the selected `--db` with native `sync --status --json`, disabling automatic import/export for diagnostic commands. Inspect tracker Git state and the configured remote. `jsonl_newer` compares content against the last certified hash, not timestamps. Distinguish a transport failure from a pending native merge receipt, Git conflicts, independently changed SQLite/JSONL, or a missing merge base. A transport-only failure may need no data reconciliation.

4. **Review the recovery plan.** Account for both local and incoming work, reservations, relationships and audit history. Use native reviewed reconciliation modes and their dry-run receipts where applicable. Select the path that matches the failure:
   - **Native publication:** ordinary exchange uses `br sync --merge --from INCOMING --base BASE` with separate pinned Git inputs, not a Git checkout merge or the JSONL merge driver. Keep canonical output selected; do not copy either input over the live export or redirect `BEADS_JSONL`.
   - **Pending native merge receipt:** `--from` refuses a pending receipt rather than treating recovery of the old merge as acceptance of fresh incoming work. Explicitly recover the old receipt with plain `br sync --merge` against the selected database, without `--from` or `--base`; verify recovery before retrying publication with freshly fetched inputs. This refusal/recovery contract is a native source capability pending final remote verification and release adoption; confirm the build before relying on it.
   - **Legacy Git conflict:** use the JSONL merge driver only for an explicitly reviewed Git-conflict recovery, not as a substitute for native publication. Review non-snapshot conflicts separately and preserve their accepted history.

   Resolve competing claims with the responsible people. Timestamps do not decide ownership. Preserve unrelated changes and use exact reviewed resolutions rather than forced synchronization, rebuilding away history or routine generated-JSONL edits. Export only after establishing that it preserves the incoming state. If supported tools cannot express the reviewed resolution, retain the evidence and request a specific recovery decision.

5. **Reconcile and verify.** Apply the agreed operations with writers still paused, inspect native sync status, and review resulting task changes and tracker commits. Verify that unpublished work and audit history survive, conflicts are resolved and the snapshot is ready for publication. Keep unrelated files out of tracker commits. Recovery publication needs the user's authorization as part of the agreed plan.

6. **Publish and release the exact incident.** Re-read the independent receipt, then use `beeswax beads sync` with `--recover` naming the current active incident, `--writers-paused` confirming the established quiescence, and `--evidence` identifying retained authorization, backups and reviewed reconciliation. These flags attest to completed work; they do not pause writers or reconcile disputed intent for you. Successful publication permits clearance of that exact incident. If publication succeeded but clearance is unverified, retain the hold and inspect confirmed effects before retrying. A further publication failure can create a new incident; re-inspect it before any retry. Never delete a receipt or rely on expiration to release the hold.

7. **Verify clearance and hand back.** Read alert status and confirm the endpoint, cleared incident and recorded evidence. Announce clearance and coordinate resumption through the owning tools. Retain the recovery record outside the tracker until ordinary writes are safe; then record any required task evidence under repository policy.
