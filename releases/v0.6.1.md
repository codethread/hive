# Hive 0.6.1

Changes since v0.6.0.

Read bundled release changes and adoption actions with `beeswax changelog`, `honeycomb changelog`, `busybee changelog`, `bee changelog`, `colony changelog`, `qlock changelog`, `hive-ui changelog` or `waggle changelog`. These eight commands work offline without project setup, a tracker or a daemon. Waggle remains development-only and is excluded from Homebrew.

Each command defaults to the latest recorded release at or below the executable's version. Use `<tool> changelog --help` for version selection, pagination and JSON output. Recorded coverage begins with selected 0.6.0 highlights; earlier history is unavailable. Per-tool histories own detailed breaking-change and required/optional adoption guidance.

## @hive/beads

No change.

## @hive/beeswax

- `beeswax update` reports the previous project version and installed tool version. Its history commands use the previous version as an exclusive `--since` baseline; same-version updates point to current history. Updating the lock does not apply or acknowledge adoption actions.
- Update receipts now offer history commands only for known Hive tool names found on `PATH`, including Waggle when present. Name lookup assumes upgraded tools; it does not check versions or supported subcommands.
- `beeswax prime` directs agents to changelogs after upgrades.

## @hive/busybee

- `busybee changelog` reads workflow-tool history without loading a workflow or opening a tracker. Its 0.6.0 record retains optional guidance for workflow-local dependencies; existing root dependency setups remain valid.
- **Breaking for Hive workflow users:** Hive Land is now 4.0.0 and Release is now 3.0.0, with mandatory changelog review and verification. Earlier incompatible saved runs require a fresh run for the remaining scope after preserving authorization and evidence and inspecting completed effects. This applies to those Hive definitions, not all Busy Bee workflows. Ordinary Land still leaves suite versions unchanged.

## @hive/colony

- `bee changelog` and `colony changelog` expose separate delegation and execution histories without accessing a tracker or contacting the daemon. Colony's history also covers its runtime, worker and watchdog companion executables.

## @hive/hive-ui

- `hive-ui changelog` prints board release history and exits without starting the web server.

## @hive/honeycomb

- `honeycomb changelog` reads worktree-tool history without a repository.
- **Breaking for archive consumers:** preserved source-message lines in squash commits now carry a Markdown blockquote prefix (`> `).
- Hive changelog authors must put authoritative top-level records in the reviewed squash body passed to `honeycomb finish --body`; quoted source archives provide provenance and do not declare release changes. Other repositories using Honeycomb do not need to adopt Hive's record format.

## @hive/qlock

- `qlock changelog` reads queue-tool history without acquiring a lock or joining a queue.

## @hive/scent

No change.

## @hive/shared

- Supplies shared history validation, version selection, pagination and human/JSON rendering for the tool changelog commands.

## @hive/tooling

- Release preparation reads top-level `changelog v1` Markdown blocks scoped to individual tools. It preserves source commit hashes, adoption guidance, breaking details and code examples while retaining previously released records.
- The record format version is independent of suite releases and workflow compatibility versions. Tool histories carry the detailed guidance; suite notes provide the package overview.

## @hive/waggle

- `waggle changelog` reads classifier-tool history without loading classifiers or making a model request.

## hive

- Adds offline changelog discovery across the suite and reviews declared tool changes through Hive's Land and Release workflows.
- Adds focused setup and contribution entry points.
- Homebrew builds Hive from tagged source on the host, with Bun as a build dependency and all runtime companions installed together.
