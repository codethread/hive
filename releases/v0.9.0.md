# Hive 0.9.0

Changes since v0.8.1.

This release includes breaking workflow, setup and Colony changes. Before upgrading, read `<tool> changelog --release 0.9.0` for detailed changes and adoption actions; Bee and Colony have separate histories. Upgrade the matching Hive suite together, following those histories for configuration changes, coordinated daemon restart and project adoption through `beeswax update --yes`.

## @hive/beads

No change.

## @hive/beeswax

- Beeswax now owns `_hive_work`, `_hive_system` and `_hive_workflows` BV recipes in application and permanent tracker checkouts. Generic and personal recipes remain user-owned. Existing locks need an explicit update before sync; custom Hive-based prompts must use the namespaced views.
- Shared onboarding requires a human's explicit instruction before assigning work to that human; existing human assignments remain protected.

## @hive/busybee

- Workflow runs, visits and groups record native succeeded, failed or cancelled outcomes. Closure alone no longer means success; old unmarked closures remain unclassified. Original stage results are preserved, and query labels are a derived index rather than completion authority.
- `busybee settle RUN cancel|fail --reason TEXT` retires only pending generated work, preserving completed work and source acceptance. Reservations, native gates and execution-clearance requirements remain; settlement neither stops workers nor recovers held locks.
- New workflow work carries `busybee-workflow` for filtering. Hive's experimental `blocked-review` and `in-progress-review` definitions are removed; inspect their unfinished runs and workers before adopting the checkout.

## @hive/colony

- Bee and Colony follow native workflow outcomes and reject request publication into retired or inconsistent scope. A stage worker follows its own visit, independently of later run cancellation.
- Colony reduces tracker reads during routing, polling and running-output publication. Wake hints shorten scans while unchanged stable-running or empty colonies use a 60-second quiet delay; stdout retains a 30-second throttle. These are scheduling limits, not freshness or completion guarantees.
- Experimental hourly reviews, post-run assessments and inactivity drones are removed. Remove retired configuration keys and callers as directed by `colony changelog` and `bee changelog`; retained history is not erased.
- `bee setup` now installs only the native `bee-attention` query. BV views belong to Beeswax, and Bee's former recipe receipt fields are removed.

## @hive/hive-ui

- Workflow previews show native outcome, terminal reason and stale-label warnings even when a definition or diagram is unavailable. Saved chart state remains separate from completion authority.
- Browser-safe outcome-schema imports keep Node-only dependencies out of the UI bundle.

## @hive/honeycomb

No change.

## @hive/qlock

No change.

## @hive/scent

No change.

## @hive/shared

- Shared contracts decode native workflow outcomes for Busy Bee, Colony and Hive UI; the outcome-schema subpath is safe for browser consumers.

## @hive/tooling

- Test runs enforce approved timing limits and report slow passing tests, with measured legacy allowances recorded explicitly. Removed slow-test coverage is documented in the repository's coverage records.

## @hive/waggle

No change.

## hive

- Repository bee-kind defaults move to Pi; installing the executables does not copy that repository configuration into consuming projects.
