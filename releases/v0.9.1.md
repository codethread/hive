# Hive 0.9.1

Changes since v0.9.0: less background work in Hive UI, connected Bee requester chains and safer cross-clone tracker publication. Per-tool `changelog` commands carry the detailed changes and adoption guidance.

## @hive/beads

- Create children with independent native hash IDs and atomic parent-child links, rather than clone-local dotted counters. Existing IDs and relationships remain valid.
- Add explicit incoming/common-base inputs for native snapshot reconciliation and selected-tracker configuration operations for lock-wait policy.

## @hive/beeswax

- Reconcile tracker snapshots through native Beads, then publish the validated export without checking files out over the live tracker. Independent changes can merge; genuine conflicts still stop for authorized recovery.
- Support an optional project `lock_timeout` policy, adopted locally through setup or update. Sync and bootstrap refuse conflicting local values.
- Report pre-publication lock contention as `tracker_busy`, without creating an incident or clearing an existing hold. Retry the checkpoint after the active publisher finishes.

**Required:** snapshot exchange needs Hive's patched native `br`, including `sync --from` and `--base`. See the installation notes below and `beeswax changelog --release 0.9.1`.

## @hive/busybee

- New runs, groups and visits use independent native IDs with parent-child links. Consumers should follow returned IDs and native relationships, not parse dotted ancestry. This does not make concurrent workflow execution across clones safe.
- Bundled execution guidance keeps commands alive through configured native tracker waits rather than cutting them off with a shorter outer timeout.

## @hive/colony

- Bee-created workflows inherit Busy Bee's independent child IDs; spawn request and response identities are unchanged.
- Bee's bundled delegation guidance accounts for native tracker waits. Colony scheduling, execution and daemon behavior are unchanged.

## @hive/hive-ui

- Keep task cards, selected details and Bee inventory on the visible-tab five-second post-load cycle; move families, descendant outlines and icons to a roughly minute-level background schedule. Batched reads and same-refresh reuse reduce repeated native work.
- Workspace Refresh and browser reload request both tiers for the current view. Inspector Refresh remains scoped to its bead and family. Slow reads, hidden tabs and stale tracker exports can still delay what appears; see the [freshness guide](../lib/hive-ui/FRESHNESS.md).
- Connect loaded Bee request cards automatically when requester matching is unique across tracker history. Explicit ancestry takes precedence; hidden requests are not loaded automatically. The graph refits to changed layout bounds and keeps its canvas visible.

**Required:** after installing the updated build, restart Hive UI and reload the browser. Coordinate with the UI owner; these changes do not require restarting Colony.

## hive

### Native dependency installation

Homebrew now builds Hive's pinned Beads fork alongside the suite instead of depending on stock `br`. Rust is a build dependency; the packaged native build disables self-update. Formula tests check the native revision and merge capabilities and warn when PATH selects another `br`.

**Required:** if stock `dicklesworthstone/tap/br` is linked, unlink it before installing the Hive formula to avoid a collision. Put Hive's `bin` directory before other `br` installations on PATH. Check `br version --json` for revision/features and `br sync --help` for `--from` and `--base`; a matching version number alone is insufficient. Update the packaged native tool through Homebrew, not `br upgrade`.

Upgrade Hive's executables together, read their changelogs, then run `beeswax update --yes` in each adopting project and review the refreshed contract and generated files. Coordinate any daemon or PATH refresh with active workers; installation alone does not replace a running Colony daemon. See the [release guide](../docs/releases.md) for installation and project adoption.
